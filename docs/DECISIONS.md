### D-1. 참고 앱(Sound Game Training) 반영 범위

**결정: 현재 설계대로 진행.** 개념(라이브러리 · 구간 반복 · 저배속 · 영상별 설정 기억)만 차용하고, 화면 구성은 PC 환경에 맞춰 새로 설계한다. [UI-BLUEPRINT.md](UI-BLUEPRINT.md)가 기준이다.

원본 앱의 UI를 1:1로 옮기지 않으므로, 이후 "참고 앱에서는 이랬는데" 류의 비교는 요구사항이 아니라 **새 제안으로 취급**한다.

### D-2. "5초(배속에 따라 조정)"의 해석

**결정: (A) 점프량 = 기준(5.0초) × 현재 배속.**

| 배속 | 실제 점프량 |
|---|---|
| 0.25x | 1.25초 |
| 0.5x | 2.5초 |
| 1.0x | 5초 |
| 2.0x | 10초 |

느리게 볼수록 관심 구간이 좁으므로 탐색 간격도 촘촘해야 한다. 결과적으로 한 번 누를 때 넘어가는 **체감(실시간) 길이가 배속과 무관하게 일정**해진다.

기준값 변경과 "배속 무관 고정" 모드는 설정으로 제공한다(FR-304). 기본값이 (A)라는 것이 이 결정의 내용이다.

### D-3. `ESC`의 동작

**결정: (B) 일시정지 전용.** `ESC`는 어떤 상황에서도 플레이어를 닫지 않는다.

| 상태 | `ESC` |
|---|---|
| 재생 중 | 일시정지 (이 순간부터 단축키 동작) |
| 일시정지 중 | **아무 일도 하지 않음** |

**근거**: 연습 중 `ESC`를 연타하게 되는 상황(멈추려다 두 번 누름)에서 플레이어가 닫혀 버리면 재생 위치·A-B 구간·배속 작업 흐름이 끊긴다. `ESC`에 파괴적 동작을 얹지 않는 편이 안전하다.

**파생 요구 — 라이브러리 복귀 경로를 따로 만들어야 한다.** `ESC`가 그 역할을 하지 않으므로:

| 경로 | 비고 |
|---|---|
| 헤더의 `◀ 라이브러리` 버튼 | 마우스 기본 경로 |
| `Alt+←` | 키보드 경로. 일시정지 상태에서만 동작 (NFR-11 충족) |
| ~~마우스 사이드 버튼 X1~~ | **폐기** — 영상 위 마우스 조작을 두지 않는다 ([D-8](#d-8-영상-위-마우스-조작-없음--재생-중-동작-키)) |

### D-4. 재생 중 차단의 예외

> **2026-09-16 부분 수정 → [D-8](#d-8-영상-위-마우스-조작-없음--재생-중-동작-키).** 아래 "예외 없음" 은 *전체화면 · 음소거 · 볼륨 · 항상 위 같은 일반 단축키* 에 대해서는 여전히 유효하다.
> 다만 재생 · 탐색 · 북마크 이동 7개 동작은 **재생 중 동작 키**로서 재생 중에도 동작하게 됐다.

**결정: (A) 예외 없음.** 재생 중 앱이 반응하는 키는 `ESC` 하나뿐이다. 전체화면(`F11`), 음소거(`M`), 볼륨(`+`/`-`), 항상 위(`T`)도 **예외가 아니다.**

**근거**: "재생 중엔 ESC만"이라는 규칙이 예외 목록을 외우는 것보다 낫다. 해당 조작은 전부 컨트롤 바에서 마우스로 도달 가능하다.

**보완 사항** — 예외를 두지 않기로 한 만큼, 마우스 경로에 구멍이 없어야 한다:

- 컨트롤 바에 전체화면 · 음소거 · 볼륨이 **모두 노출되어 있어야 한다** (누락 시 재생 중 조작 불가)
- ~~영상 더블클릭 = 전체화면 (FR-207)~~ — [D-8](#d-8-영상-위-마우스-조작-없음--재생-중-동작-키) 로 폐기. 전체화면은 컨트롤 바 버튼으로
- 키보드의 **미디어 키(볼륨 업/다운/음소거)는 재생 중에도 동작한다.** 앱이 그 키를 가로채지 않기 때문 — 시스템 볼륨이 바뀌는 방식이며, 이는 차단 대상이 아니다

### D-5. 북마크 5개의 의미

**결정: 슬롯 방식.** 1~5번 고정 칸. `Ctrl+3` 저장 / `3` 점프 (일시정지 상태에서).

리듬게임 연습에서는 "그 구간"을 즉시 부르는 것이 핵심이므로, 순서가 밀리는 목록형보다 번호가 고정된 슬롯이 맞다. 빈 슬롯도 UI에 항상 5칸 노출해 남은 칸이 한눈에 보이게 한다.

슬롯을 넘는 자유 북마크는 P2(FR-327).

### D-6. 라이선스 / 공개 방침

**결정: 당분간 개인 사용. 추후 오픈소스 공개 가능성을 열어 둔다.**

이에 따른 실무 방침:

| 항목 | 방침 |
|---|---|
| 현재(배포하지 않음) | GPL 계열 libmpv 빌드를 써도 의무가 발생하지 않는다. GPL 의무는 **배포 시점**에 생긴다 |
| 향후 대비 | 그래도 **LGPL 구성 libmpv 빌드를 우선 확보**한다. 나중에 "공개는 하되 GPL은 피하고 싶다"가 되어도 엔진을 바꾸지 않아도 되도록 |
| 코드 구조 | `IMediaEngine` 추상화를 유지해 엔진 교체 가능성을 열어 둔다 (이미 반영됨, SPEC §9.2) |
| 문서 | `docs/THIRD-PARTY.md`를 **처음부터** 작성하고 의존성 추가 시마다 갱신한다. 나중에 소급 정리하는 것이 훨씬 비싸다 |
| 소스 관리 | 공개 전환을 대비해 **비밀값·개인 경로·캡처 영상을 저장소에 넣지 않는다** |

공개를 실제로 결정하는 시점에 이 항목을 갱신한다.

### D-7. 마일스톤 우선순위

**결정: 조정 없음.** M1(MVP)은 P0 요구사항만 담고, A-B 구간 반복(FR-601)을 포함한 P1 항목은 M2에 둔다.

M1을 좁게 유지하면 **실제로 써 보고 나서** M2 우선순위를 정할 수 있다. 사용 후 "A-B 루프가 없으면 못 쓰겠다"가 되면 그때 M2 최상단으로 올린다.

### D-8. 영상 위 마우스 조작 없음 · 재생 중 동작 키

**결정일: 2026-09-16** (M1 수동 사용 중 사용자 요청)

**배경**: M1 은 D-4 로 재생 중 키가 전부 막히자, 재생 중 조작 경로를 **영상 위 마우스 제스처**(클릭 재생/일시정지 · 휠 점프 · 우클릭 드래그 프레임 · 사이드 버튼 북마크)로 두었다. 사용해 보니 두 문제가 드러났다.

- **마우스를 쓰는 리듬게임이 있다.** 따라 치다가 영상을 건드리면 재생이 멈추거나 위치가 튄다 — 키보드 차단(D-4)으로 막으려던 사고가 마우스로 그대로 재발한다.
- 그렇다고 마우스를 막으면 재생 중에는 ESC 외에 할 수 있는 게 없어 불편하다.

**결정**

| 항목 | 내용 |
|---|---|
| 영상 위 마우스 | **아무 동작도 하지 않는다.** 클릭 · 휠 · 우클릭 · 가운데 · 사이드 버튼 전부 버린다. (컨트롤 바 · 타임라인 등 영상 바깥 UI 는 그대로 마우스로 쓴다) |
| 재생 중 동작 키 | 원래 마우스에 있던 7개 동작을 키로 옮기고, **재생 중에도 동작**하게 한다 |
| 기본 배치 | F1 뒤로 점프 · F2 프레임 뒤로 · F3 프레임 앞으로 · F4 앞으로 점프 · F5 재생/일시정지 · F6 이전 북마크 · F7 다음 북마크 |
| 변경 | 설정에서 **ESC 를 제외한 아무 키**로나 바꿀 수 있다. 해제도 가능 |

**근거와 세부 규칙**

- **F키를 기본으로 쓰는 이유** — 대부분의 리듬게임이 쓰지 않는다. 그래도 겹칠 수 있어 변경을 허용한다.
- **F10 · F11 · F12 는 기본값에서 뺐다.** F10 은 Alt 와 같은 시스템 메뉴 키, F11 은 M2 전체화면 예정, F12 는 Windows 가 디버거용으로 예약한다.
- **F1 → F4 는 왼쪽에서 오른쪽으로 시간이 앞으로 간다.** 손가락 위치로 방향을 외울 수 있게.
- **ESC 는 지정 불가.** 일시정지 전용(D-3)이고, 설정 창에서 키 입력을 기다릴 때 "취소" 로 쓴다.
- **다른 동작이 쓰던 키를 고르면 맞바꾼다.** 조용히 해제되는 동작이 생기지 않게.
- **다른 수정자와 함께 누르면 동작하지 않는다.** `Alt+F4`(창 닫기)가 "앞으로 점프" 까지 일으키면 안 되기 때문. 지정한 키가 수정자 자신(예: 오른쪽 Ctrl)이면 그 플래그는 무시한다.
- **일시정지 중에도 다른 단축키보다 우선한다.** 예컨대 Space 를 지정했다면 상태에 따라 뜻이 달라지면 헷갈린다.
- **자동 반복** — 점프 · 프레임은 누르고 있으면 계속 이동한다. 재생/일시정지 · 북마크 이동은 반복을 무시한다(초당 수십 번 토글되지 않게).
- **텍스트 입력 중에는 동작하지 않는다.** FR-509 가 여전히 최우선.

**D-4 와의 관계**: 전체화면 · 음소거 · 볼륨 · 항상 위 등 일반 단축키는 여전히 재생 중 예외 없이 막힌다. 재생 중 동작 키만 명시적으로 허용한 목록이다.

**구현 · 검증**: [M1-PROGRESS §7](M1-PROGRESS.md#7-d-8-반영--영상-위-마우스-조작-제거와-재생-중-동작-키)
