## 1. 전체화면 (FR-207)

### 결정

| 항목 | 내용 | 이유 |
|---|---|---|
| 진입 · 해제 | 컨트롤 바 `⛶` 버튼, **F11** | F11 은 D-8 에서 전체화면용으로 비워 뒀던 키 |
| F11 의 성격 | **재생 중 동작 키의 8번째**로 추가 — 재생 중에도 동작, 설정에서 변경 가능 | 전체화면 전환은 재생을 방해하지 않는다. 재생 중 막으면 따라 치다가 크기를 바꿀 수 없다 ([D-8](DECISIONS.md#d-8-영상-위-마우스-조작-없음--재생-중-동작-키) 보완) |
| 화면 구성 | 창 테두리 · 작업 표시줄 · 상단 바를 없애고, **하단 컨트롤은 남긴다** | 영상 위에 컨트롤을 겹칠 수 없어서(airspace), 재생 중 숨겼다 보이면 영상 크기가 바뀌며 화면이 출렁인다 |
| ESC | 일시정지만. 전체화면은 유지 | D-3 |
| 라이브러리로 돌아가면 | 창 모드로 | 전체화면은 플레이어에서만 의미가 있다 |

**재생 상태 표시**: 상단 바의 배지(FR-505)가 전체화면에서는 숨지만, 재생 중 영상 테두리가 앰버로 바뀌고 하단 안내가 보이므로 상태는 계속 알 수 있다.

### 구현 메모

- 이미 최대화된 창에서 테두리만 없애면 작업 표시줄을 덮지 않는다. WPF 는 **최대화하는 순간의 창 스타일**로 크기를 정하므로, 한 번 `Normal` 로 돌렸다가 다시 최대화한다. 나올 때도 같은 이유로 `Normal` 을 거친다.
- 창 모양이 바뀐 뒤에도 키보드 포커스를 창으로 되돌린다 — 놓치면 ESC 와 F키가 먹지 않는다(M0 의 교훈).
- 전체화면 항목이 없던 옛 `settings.json` 은 F11 을 자동으로 받는다. 옛 설정에서 F11 을 이미 다른 동작에 썼다면 전체화면은 해제 상태가 된다(한 키가 두 동작을 일으키지 않게).

### 검증 (종단 5-5 단계 · 7/7)

```
✓ 버튼 → 테두리 없는 최대화                  None · Maximized
✓ 영상이 커짐                                1236 → 1916 (화면 1920)
✓ 전환 후에도 포커스가 창에 있음             MainWindow
✓ 재생 중 F11 → 창 모드로, 재생은 계속
✓ 창 크기가 원래대로                         1280 → 1280
✓ 재생 중 F11 → 다시 전체화면
✓ ESC 는 일시정지만 (전체화면 유지, D-3)
✓ 전체화면에서 라이브러리로 복귀하면 창 모드로
```

단위: 기본 배치에 F11 포함, 옛 설정 파일 호환 2건 추가. 게이트 전수 테스트의 "재생 중 통과하는 키" 에 F11 추가.

### 변경: 영상이 화면을 꽉 채우고, 컨트롤은 떠 있는 바로 (사용자 요청)

| 항목 | 내용 |
|---|---|
| 영상 | 전체화면에서 테두리 · 여백 없이 화면 전체 |
| 컨트롤 | 화면 아래에 반투명 둥근 바로 **겹쳐 띄운다**. 창 모드로 돌아가면 원래대로 영상 아래에 붙는다 |
| 표시 시점 | **일시정지 중에만** 보인다. 재생을 시작하면 사라지고 ESC 로 일시정지하면 다시 뜬다. 재생 중에는 화면에 아무것도 겹치지 않는다 |

위 "화면 구성" 결정(컨트롤을 남겨 둠)을 대체한다. 재생 중에는 바가 아예 뜨지 않으므로 영상 크기가 출렁이는 문제는 생기지 않는다.

구현 메모:

- 영상(HwndHost) 위에 같은 창의 WPF 요소는 겹칠 수 없다(airspace). 바는 **투명한 별도 창**(`FloatingControlsWindow`, 주 창 소유)이고, 플레이어 화면의 컨트롤 요소를 **그대로 떼어 옮긴다** — 바인딩 · 타임라인 처리기 · 북마크 메뉴가 복제 없이 따라간다.
- ★ 바는 절대 활성화되면 안 된다. 활성화되면 주 창이 비활성화되어 일시정지되고(FR-507), ESC · 동작 키가 입력 가드에 닿지 않는다. `WS_EX_NOACTIVATE` + `WM_MOUSEACTIVATE → MA_NOACTIVATE` 로 클릭해도 활성화되지 않게 하고, 버튼이 포커스를 가져가려는 것은 `PreviewGotKeyboardFocus` 에서 막는다.
- 영상 테두리 두께를 요소 속성으로 두었더니 전체화면 트리거가 덮어쓰지 못해 가장자리 2px 이 남았다 → 스타일 세터로.
- 자동 검증의 실제 마우스 클릭(`mouse_event`)은 **그 지점의 창이 이 앱일 때만** 누른다. 다른 프로그램이 앞에 있으면 그 프로그램을 클릭하게 되므로 건너뛰고 실패로 기록한다.

검증 (5-5 단계 추가분):

```

✓ 일시정지 중: 컨트롤이 떠 있는 바로 보임
✓ 바는 화면 아래쪽에 겹쳐 뜸                top 888 · 높이 192
```

## 2. 폴더 · 검색 · 태그 · 폴더별 기본 오프셋 (FR-104 · 106 · 107 · 405)

### 결정

| 항목 | 내용 | 이유 |
|---|---|---|
| 목록 | "최근 재생" 대신 **등록된 모든 영상을 한 목록**에. 기본 정렬은 최근 재생 순(재생 안 한 영상은 뒤, 최근 추가 순) | 폴더에서 올라온 영상은 재생 기록이 없어서 최근 목록에는 안 보인다 |
| 정렬 | 최근 재생 · 최근 추가 · 제목 · 많이 재생 | SPEC 의 "길이" 대신 "최근 추가" — 새 녹화를 찾는 일이 더 잦다. 길이는 한 번 열어야 알 수 있어 스캔 직후엔 비어 있다 |
| 검색 | 제목 **또는 태그 이름**에 포함. 공백으로 나눈 낱말이 **모두** 맞아야 함. 250ms 디바운스 | "conflict 트릴" 처럼 좁혀 가기 |
| 태그 | 카드 우클릭 → 태그 편집(쉼표 구분). 태그 칩을 누르면 거르고 다시 누르면 해제 | 입력은 앞 `#` 제거 · 공백 정리 · 대소문자만 다른 중복은 기존 표기로 합침 · 30자 · 영상당 20개. 아무 영상에도 안 붙은 태그는 지운다 |
| 스캔 시점 | 앱 시작 시(목록을 먼저 보여 주고 뒤에서), 폴더 창을 닫을 때 | 실시간 감시는 P2 |
| 스캔 비용 | **경로와 크기가 같은 파일은 지문을 다시 계산하지 않는다** | 지문은 파일당 2MB 를 읽는다. 외장 HDD 의 수백 편을 매번 읽으면 느리다 |
| 옮긴 파일 | 스캔에서 새 경로로 지문 계산 → 같은 지문이면 기존 영상의 경로를 갱신 | 북마크 · 오프셋 · 태그가 따라간다 |
| 오프셋 우선순위 | **영상별 값 > 기본값이 지정된 가장 가까운 폴더 > 0** | 상위 폴더에 +33, 하위 폴더는 "지정 안 함"이면 +33 을 받는다. 전역 기본값은 아직 없음 |
| 영상별 값의 뜻 | 플레이어에서 오프셋을 조정하면 그 영상만의 값이 된다 (0 도 명시적인 값). **[폴더값]** 버튼으로 지우고 폴더 값을 따른다 | 폴더 값을 바꿨을 때 조정해 둔 영상까지 바뀌면 안 된다 |
| 폴더 등록 해제 | 파일은 건드리지 않는다. **사용자 기록이 전혀 없는 영상**(재생 · 북마크 · 태그 · 영상별 오프셋 없음)만 목록에서 빼고, 다른 등록 폴더에도 속한 영상은 남긴다 | 폴더를 잘못 등록했을 때 되돌릴 수 있어야 하고, 쌓은 기록은 잃지 않아야 한다 |
| 열리지 않는 파일 | 직접 연 파일이 열리지 않으면 방금 등록된 기록을 지운다 (등록 폴더 안의 파일은 남긴다 — 스캔이 어차피 다시 올린다) | M1 에서는 최근 목록이 재생한 영상만 보여서 드러나지 않던 문제 |

### 구현 메모

- DB 스키마 v2: `folders`(경로 `COLLATE NOCASE` 고유, 기본 오프셋 NULL 허용) · `tags`(이름 `NOCASE` 고유) · `video_tags`. v1 DB 는 앱 시작 시 자동으로 올라가며 기존 데이터는 그대로다 (단위 테스트로 확인).
- 폴더 경로 포함 판정은 SQL `LIKE` 대신 `FolderRules.Contains` 한 곳에서 한다 — `D:\rec` 가 `D:\recording\…` 을 포함하지 않게(경계), 대소문자 무시.
- 스캔은 `Task.Run` 에서 돈다. 지문 계산과 SQLite 호출에 동기 IO 가 섞여 있어 UI 스레드에서 돌리면 화면이 멈춘다. 숨김 · 시스템 파일과 권한 없는 하위 폴더는 건너뛴다. 잠긴 파일(녹화 중)은 "읽지 못함"으로 세고 다음 스캔에서 다시 시도한다.
- 앱 전역 `TextBlock` 스타일이 버튼 안에서 자동 생성되는 TextBlock 의 글자색을 덮어써서, 선택된 칩 · "등록 해제" 의 색이 안 바뀌었다 → 버튼 안에 TextBlock 을 직접 두었다. 공용 버튼 템플릿이 `HorizontalContentAlignment` 를 무시하던 것도 고쳤다(썸네일 없는 카드가 가운데로 쪼그라듦).
