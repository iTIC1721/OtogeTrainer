## 1. 전체화면 (FR-207)

### 결정

| 항목 | 내용 | 이유 |
|---|---|---|
| 진입 · 해제 | 컨트롤 바 `⛶` 버튼, **F11** | F11 은 D-8 에서 전체화면용으로 비워 뒀던 키 |
| F11 의 성격 | **재생 중 동작 키의 8번째**로 추가 — 재생 중에도 동작, 설정에서 변경 가능 | 전체화면 전환은 재생을 방해하지 않는다. 재생 중 막으면 따라 치다가 크기를 바꿀 수 없다 ([D-8](DECISIONS.md#d-8-영상-위-마우스-조작-없음--재생-중-동작-키) 보완) |
| 화면 구성 | 창 테두리 · 작업 표시줄 · 상단 바를 없애고, **하단 컨트롤은 남긴다** | 영상 위에 컨트롤을 겹칠 수 없어서(airspace), 재생 중 숨겼다 보이면 영상 크기가 바뀌며 화면이 출렁인다 |
| ESC | 일시정지만. 전체화면은 유지 | D-3 |
| 라이브러리로 돌아가면 | 창 모드로 | 전체화면은 플레이어에서만 의미가 있다 |

**재생 상태 표시**: 상단 바의 배지(FR-505)가 전체화면에서는 숨지만, 재생 중 영상 테두리가 앰버로 바뀌고 하단 안내가 보이므로 상태는 계속 알 수 있다.

### 구현 메모

- 이미 최대화된 창에서 테두리만 없애면 작업 표시줄을 덮지 않는다. WPF 는 **최대화하는 순간의 창 스타일**로 크기를 정하므로, 한 번 `Normal` 로 돌렸다가 다시 최대화한다. 나올 때도 같은 이유로 `Normal` 을 거친다.
- 창 모양이 바뀐 뒤에도 키보드 포커스를 창으로 되돌린다 — 놓치면 ESC 와 F키가 먹지 않는다(M0 의 교훈).
- 전체화면 항목이 없던 옛 `settings.json` 은 F11 을 자동으로 받는다. 옛 설정에서 F11 을 이미 다른 동작에 썼다면 전체화면은 해제 상태가 된다(한 키가 두 동작을 일으키지 않게).

### 검증 (종단 5-5 단계 · 7/7)

```
✓ 버튼 → 테두리 없는 최대화                  None · Maximized
✓ 영상이 커짐                                1236 → 1916 (화면 1920)
✓ 전환 후에도 포커스가 창에 있음             MainWindow
✓ 재생 중 F11 → 창 모드로, 재생은 계속
✓ 창 크기가 원래대로                         1280 → 1280
✓ 재생 중 F11 → 다시 전체화면
✓ ESC 는 일시정지만 (전체화면 유지, D-3)
✓ 전체화면에서 라이브러리로 복귀하면 창 모드로
```

단위: 기본 배치에 F11 포함, 옛 설정 파일 호환 2건 추가. 게이트 전수 테스트의 "재생 중 통과하는 키" 에 F11 추가.
