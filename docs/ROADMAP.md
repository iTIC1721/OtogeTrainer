## 2. 작업 순서 의존성

```
M0 (스택 확정)
   │
   ├─▶ IMediaEngine + MpvMediaEngine  ─┐
   ├─▶ IInputGate + 단축키 맵          ─┼─▶ PlayerViewModel ─▶ M1 플레이어
   └─▶ Data(SQLite) + 지문 계산        ─┘        │
                                                └─▶ LibraryViewModel ─▶ M1 라이브러리
```

- `IMediaEngine`과 `IInputGate`는 **서로 의존하지 않으므로 병렬 진행 가능**. 입력 게이트는 순수 함수라 단위 테스트로 대부분 검증된다.
- 데이터 계층은 지문 계산(§SPEC 5.1)이 확정돼야 시작 — 스키마가 여기에 매여 있다.

## 3. 검증 계획

### 3.1 프레임 정확도 검증 클립

프레임 번호와 타임코드가 화면에 번인된 60fps CFR 클립을 만들어, 스텝/점프 후 **화면에 보이는 숫자**와 **앱이 표시하는 숫자**가 일치하는지 눈으로 확인한다.

```bash
ffmpeg -f lavfi -i testsrc2=size=1280x720:rate=60 -vf "drawtext=text='F %{n}   T %{pts\:hms}':fontsize=54:fontcolor=white:box=1:boxcolor=black@0.6:x=40:y=40" -t 120 -c:v libx264 -preset veryfast -pix_fmt yuv420p tests/assets/frametest_60fps_cfr.mp4
```

같은 방식으로 **30fps**, **59.94fps(드롭프레임)** 버전도 만든다. VFR 검증용으로는 OBS로 실제 녹화한 짧은 클립을 사용한다(합성으로 재현하기 어렵다).

| 케이스 | 기대 |
|---|---|
| 프레임 앞으로 1회 | 번인 `F` 값 정확히 +1 |
| 프레임 뒤로 1회 | 정확히 −1 |
| 프레임 뒤로 60회 연속 | 정확히 −60, 누적 오차 0 |
| 1.0x에서 `→` | +5.000초 |
| 0.5x에서 `→` | +2.500초 |
| 2.0x에서 `→` | +10.000초 |
| 북마크 저장 → 다른 곳으로 이동 → 점프 | 저장 시점과 **동일 프레임** |
| 저장 → 앱 재시작 → 같은 영상 열기 | 같은 프레임, 같은 배속, 같은 오프셋 |

### 3.2 A/V 오프셋 검증 클립

1초 주기로 **화면 전체가 1프레임 흰색으로 플래시** + **동시에 짧은 클릭음**이 나는 30초 클립을 준비한다(직접 생성하거나 공개 A/V sync 테스트 패턴 사용).

| 케이스 | 기대 |
|---|---|
| 오프셋 0 | 플래시와 클릭음이 동시 |
| `+100ms` | 소리가 눈에 띄게 늦음 |
| `-100ms` | 소리가 눈에 띄게 빠름 |
| 재생 중 변경 | 끊김/팝 노이즈 없이 즉시 반영 |
| 재시작 후 | 저장값 자동 적용 |

### 3.3 재생 중 단축키 차단 검증 (수동 체크리스트)

SPEC §6.2의 누출 경로 표가 곧 이 체크리스트다. **재생 중 어떤 키를 눌러도 영상이 계속 흘러가야 한다.**

재생 중 (설정 FR-508 OFF 상태):

- [ ] `Space` 난타 → 재생 멈추지 않음
- [ ] `←` `→` `↑` `↓` 난타 → 위치 · 배속 변화 없음, 포커스 이동 없음
- [ ] `1`~`5`, `,` `.` `[` `]` `A` `B` `L` `S` → 아무 반응 없음
- [ ] 컨트롤 바 버튼을 마우스로 누른 **직후** `Space` → 그 버튼이 다시 눌리지 않음 (§6.2-2)
- [ ] 타임라인 슬라이더를 만진 **직후** `←` → 값이 움직이지 않음 (§6.2-3)
- [ ] `Tab` 연타 → 포커스 링이 돌아다니지 않음 (§6.2-5)
- [ ] `Alt` 단독 / `F10` → 시스템 메뉴 안 열림 (§6.2-6)
- [ ] `Alt+Space` → 창 시스템 메뉴 안 열림
- [ ] 한/영 키, 한자 키 → 아무 반응 없음
- [ ] 영상 영역 클릭 후 키 입력 → mpv 기본 바인딩 발동 없음 (§6.2-7)
- [ ] 10초간 무작위 난타 → 재생 위치가 정확히 10초만 진행

경계 조건:

- [ ] `ESC` → 즉시 일시정지, 배지 🔓 전환
- [ ] 일시정지 상태에서 모든 단축키 정상 동작
- [ ] 일시정지 상태에서 `ESC` 연타 → **아무 일도 일어나지 않음** (플레이어가 닫히지 않을 것, D-3)
- [ ] `Alt+←` / `◀ 라이브러리` 버튼 → 라이브러리 복귀, 재생 위치·배속·오프셋 저장됨 (FR-511)
- [ ] 재생 중 `F11` `M` `+` `-` `T` → **동작하지 않음** (D-4: 예외 키 없음)
- [ ] 재생 중 컨트롤 바로 전체화면 · 음소거 · 볼륨 · 항상 위에 전부 도달 가능 (R7)
- [ ] 재생 중 키보드 미디어 볼륨 키 → 시스템 볼륨 정상 변경
- [ ] 북마크 라벨 입력 중 `Space`/방향키 → **정상 입력됨** (FR-509)
- [ ] 라이브러리 검색창 입력 중 → 정상 입력됨
- [ ] 설정에서 "재생 중에도 단축키 허용" ON → 재생 중 단축키 동작

전역에 영향이 없음을 확인 (메모장/브라우저를 함께 띄운 상태):

- [ ] 재생 중 `Alt+Tab`으로 메모장 전환 → 타이핑 정상
- [ ] `Win` → 시작 메뉴 정상
- [ ] 앱으로 돌아오면 일시정지 상태 (FR-507)
- [ ] 앱 최소화 중 다른 프로그램 단축키 전부 정상

### 3.4 자동화 테스트 범위

| 대상 | 방식 |
|---|---|
| 점프량 계산, 배속 클램프, 오프셋 클램프, 북마크 슬롯 규칙 | 단위 테스트 (순수 로직) |
| 지문 계산 · 파일 재연결 로직 | 단위 테스트 (임시 파일) |
| DB 마이그레이션 | 단위 테스트 (v0→v1 시나리오) |
| 엔진 시크/스텝 정확도 | 통합 테스트 (검증 클립 + 실제 libmpv, CI에서는 스킵) |
| **입력 게이트 판정 로직** | 단위 테스트 — `IInputGate.Evaluate`는 순수 함수이므로 (키 × 재생상태 × 텍스트포커스 × 설정) 조합을 전수로 검증 가능 |
| WPF 기본 동작 누출 (§6.2) | 수동 체크리스트 (§3.3) — 실제 포커스/렌더 트리 상태가 얽혀 자동화 가치가 낮음 |

## 5. 배포 · 라이선스

### 배포 형태

- **무설치 zip** 우선 — `OtogeTrainer.exe` + `libmpv-2.dll` + 런타임(self-contained, x64). 관리자 권한 불필요(NFR-10).
- 설치 프로그램(MSIX/Inno)과 코드 서명은 선택 사항. 시스템 후킹을 쓰지 않으므로 SmartScreen 경고 완화 목적 외에는 급하지 않다.
- 자동 업데이트는 v1 범위 밖. 앱 내 "새 버전 확인" 링크만.

### 라이선스 확인 필요 (배포 전 필수)

| 구성요소 | 라이선스 | 조치 |
|---|---|---|
| libmpv | 공식 배포 바이너리는 GPLv2+ 구성이 일반적. **LGPL 구성으로 빌드 가능** | **LGPL 빌드를 우선 확보**(D-6) |
| (대안) libvlc / LibVLCSharp | LGPLv2.1+ | 동적 링크 유지 시 비교적 자유로움 |
| .NET 8, CommunityToolkit.Mvvm, Dapper, Serilog | MIT류 | 고지만 |

> **확정([D-6](DECISIONS.md#d-6-라이선스--공개-방침))**: 당분간 개인 사용, 추후 오픈소스 공개 가능성은 열어 둔다.
